# Chunk preprocessing — redesign plan

Redesign of the `summaries` feature into a general **chunk-preprocessing** stage that produces
**first-class embedding variants**.

## Status — implemented (2026-07)

Built in commit `47de423` (plan: `a21531f`). All 12 decisions and the full implementation/removal
work below landed; 451 unit tests green, lint clean.

- **Verified:** unit tests (registry identity, config, chroma naming, cli, pipeline caches), and a
  logic smoke of `preprocess.py` (prompt load, hash + whitespace normalisation, cache resume without
  an LLM call) and variant resolution.
- **Not yet exercised:** a real end-to-end run (`mytho embeddings --model bge-m3-summary` → Chroma →
  search) — needs models + an LLM key; run once in a real environment.
- **Deferred from decision C:** `clean --caches` sweeps `outputs/preprocessed/` **wholesale** (like
  every other resumable cache), not the reachability-based orphan-only GC — consistent with the
  existing `--caches` semantics; the finer GC can be added later if needed.

## Goal

Today "summaries" is an opt-in projection (`mytho projections --summaries`) that LLM-summarises each
chunk, embeds the summaries in memory, and writes one extra 2D scatter (`summaries_umap.json`). The
summary vectors never reach Chroma, so there is no nearest-neighbour search over them, and the
summaries are regenerated once per model.

The redesign makes preprocessing a property of an **embedding model variant**:

- preprocessing runs at the **`embeddings`** stage, not `projections`;
- the variant is its **own Chroma collection**, with the normal projections and nearest-neighbour
  search over it — like any other model;
- it is enabled by an **entry in `config/models.json`**, not a CLI flag;
- summary is just **one** preprocessing prompt; the mechanism is generic.

## Settled decisions

| # | Decision |
|---|----------|
| 1 | Summary → generic **chunk preprocessing**; a first-class embedding variant (own Chroma collection, own search). |
| 2 | Enabled by a `config/models.json` entry, **not** a CLI flag. |
| 3 | **Identity = the entry's alias key** (author-assigned), decoupled from the base HF id. It is the single key used for the Chroma collection, output/cache folders, API paths, and the dropdown `value`. Charset: `[a-z0-9._-]`, 3–63 chars, starts/ends alphanumeric — validated at registry load. |
| 4 | `label` is **optional**; when absent it is generated by humanising the key (split on `. _ -`, join with ` · `, capitalise tokens). |
| 5 | One optional **`preprocess_prompt`** field (a name resolved in `config/prompts.json`) replaces the earlier `input` + `summary_prompt` idea. Present → preprocessing mode; value → which prompt. |
| 6 | Embedder input prefixes stay **inline** in `models.json`, renamed `query_prefix` / `document_prefix`. Naming rule: **`*_prompt` = reference into `config/prompts.json`; `*_prefix` = inline literal**. |
| 7 | Prompts in `config/prompts.json` are **plain standalone strings** — no templating, no includes. |
| 8 | Preprocessing cache identity = **content hash of the resolved prompt text** (name kept for legibility). Layout `outputs/preprocessed/<prompt-name>.<short-hash>.jsonl`; record carries `{prompt, prompt_hash, value}`. Text normalised (trim + collapse whitespace) before hashing. |
| 9 | Cache is **model-independent and shared**, keyed by `(prompt_hash, chunk_hash)` — one prompt generates each chunk once regardless of how many models embed it. |
| A | **No collection manifest / staleness fingerprint.** A prompt/chunking edit needs a manual `mytho embeddings --force` to rebuild the collection (the collection resumes by positional `chunk_id`, so this matches current behaviour — no new footgun, existing one not fixed). |
| B | **Graphs untouched.** They keep their chunk-only extraction cache; their latent stale-on-prompt-edit stays as is. |
| C | Obsolete `preprocessed` caches are GC'd by **`mytho clean --caches`**, by reachability from the current `models.json` (live = prompt-hashes referenced now). Retained by default (enables rollback); removed only on the explicit command. |

## `models.json` embedding entry — target schema

| Field | Req | Default | Meaning |
|-------|-----|---------|---------|
| `<alias>` (the key) | yes | — | Canonical variant id (see decision 3). |
| `model` | yes | — | Base HF model id. |
| `label` | no | autogen from key | Display name (UI, logs). |
| `preprocess_prompt` | no | none (embed raw text) | Name in `config/prompts.json`; enables preprocessing. |
| `query_prefix` | no | `""` | Inline query-side input prefix/instruction (model-specific). |
| `document_prefix` | no | `""` | Inline document-side input prefix (empty for query-only models: BGE, Qwen3). |
| `dtype` | no | `auto` | Encoder dtype. |
| `batch_size` | no | from settings | Encode batch size. |

Sections: `embedding.models` (active, visible to code) vs `embedding.inactive` (invisible).

## Implementation work

1. **Registry (`model_registry.py`)** — make the alias the primary key; resolve alias → full config; validate charset + uniqueness; `label = entry.get("label") or humanize(alias)`; surface `preprocess_prompt`, `query_prefix`, `document_prefix`; `active_embedding_models` / `list_*` return aliases; `model_name_for_key` → alias→HF id.
2. **Preprocessing stage (embeddings)** — a generic step that, for a variant with `preprocess_prompt`, resolves the prompt, generates per-chunk preprocessed text via the LLM into the shared `outputs/preprocessed/…` cache (resumable, rate-limited — port the resilience from the old `run_summaries`), then feeds that text (instead of raw) to the encoder for that variant's collection.
3. **`build_embeddings`** — branch on `preprocess_prompt`: raw text vs preprocessed text as encoder input; everything downstream (Chroma collection, projections, search) is unchanged.
4. **Frontend** — dropdown already keys on `{key, label}`; no summary-specific code once `summaries_umap` is gone.
5. **`clean --caches`** — extend orphan detection to the `preprocessed` cache by reachability.

## Removal / obsolete tails

**Delete / migrate logic:**
- `src/projections/summaries.py` (whole module: `generate_summaries` / `embed_summaries` / `run_summaries` / `load_summary_prompt`, incl. the >50%-empty guard and resilience → move to the preprocessing stage).
- `src/projections/build_projections.py` — `summaries=` param, `_generate_summary_plot`, the `summaries_umap` special-case in `_generate_plots`.
- `src/projections/__init__.py` — the `summaries_umap` entry in `PROJECTION_METHODS`.
- `src/cli.py` — the `--summaries` flag on `projections` and its passthrough via `_build_projections`.

**Tails to update / clean:**
- Frontend: "Summary UMAP" drops from the dropdown once `summaries_umap` leaves `PROJECTION_METHODS` (no dedicated code).
- Stale on-disk artefacts: `outputs/projections/<model>/summaries_umap.json`, `summaries.jsonl` → orphaned, cleaned via `clean --caches`.
- Help/docstrings mentioning summaries: `cli.py` `--caches` help, `chunk_cache.py` docstring, `export_bundle.py`, `docs/how-to.md` (`--summaries` / Summary UMAP).
- Tests: audit for summaries references (`test_cli`, …).

**Keep:** the `summary` key in `config/prompts.json` — now the target of `preprocess_prompt`.

```json
"bge-m3-summary": {
  "model": "BAAI/bge-m3",
  "preprocess_prompt": "summary",
  "label": "BGE-M3 · summary"
}
```

## Documentation

Add a full **embedding-entry schema** section to `docs/how-to.md` (the table above — most existing
fields are currently undocumented), state the `*_prompt` = reference / `*_prefix` = inline rule
explicitly, note the model-specific nature of prefixes (E5 `passage:` / Qwen & BGE query-only), and
remove the `--summaries` / Summary-UMAP references.

## Non-goals

Templating / prompt includes; collection staleness manifest; changes to the graph pipeline;
per-model preprocessing cache; automatic (non-`clean`) cache GC.
