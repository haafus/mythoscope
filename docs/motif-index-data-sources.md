# Традиционные индексы мотивов: источники данных и их интеграция

*Обзор машиночитаемых источников по фольклорно-мифологическим индексам (Берёзкин, Thompson/TMI, Aarne–Thompson–Uther/ATU) и план их использования в mythoscope. Связан с пунктами roadmap 1 («Relate unsupervised results to traditional motif indexes»), 2 («Query index by traditional motives») и 7 («Integrate traditional indexes (ATU, Berezkin)»).*

## TL;DR

- Из пяти просмотренных ресурсов **сразу пригоден один — датасет Trilogy** (`github.com/j-hagedorn/trilogy`, CC-BY-SA 4.0): набор «tidy» CSV-таблиц, который уже связывает три уровня — **тексты сказок → типы ATU → упорядоченные мотивы TMI**, плюс функции Проппа и готовые графы. Это и есть «розеттский камень», которого не хватало для привязки наших безнадзорных кластеров к традиционным индексам.
- **Машиночитаемый TMI** (`github.com/fbkarsdorp/tmi`, Apache-2.0) даёт полный индекс Томпсона в JSON + поисковик; Trilogy уже включает ту же таблицу TMI в виде CSV с разобранной иерархией, так что fbkarsdorp нужен в основном как сверочный/обогащающий источник и как пример индексации (Whoosh).
- **База Берёзкина** (`mapsofmyths.com/motifs`, `areasofmyths.com`) — уникальна по двум причинам: (а) ареальное распределение мотивов по ~958 обществам и (б) явные соответствия между мотивами Берёзкина и TMI/ATU. Но она под паролем/копирайтом, без выгрузки и API; бирюзовый веб-зеркало `folkloredatabase.com` прямо запрещает text/data mining. Использовать можно **только** опубликованные академические выгрузки и таблицы соответствий, либо по прямой договорённости с держателями — не скрейпингом.
- **ATU-тезаурус** на `vocabularyserver.com/atu` — это инсталляция TemaTres, то есть SKOS/RDF/JSON выгружаются «из коробки»; полезен как канонический, многоязычный, ссылающийся на DBpedia слой типов сказок. Гайды библиотеки Миссури — это не конкорданс, а кураторские списки полнотекстовых сказок по номерам ATU (ссылки на Internet Archive) — годятся как маленький размеченный корпус.
- **Как использовать в mythoscope:** (1) gold-стандарт для оценки индуцированных мотивов/кластеров (item 1); (2) контролируемый словарь и cross-walk для запроса «по традиционному мотиву» (item 2); (3) размеченный корпус `aft` для few-shot/fine-tune детекции мотивов в духе GOLEM / Arabian Nights (см. `motif-induction-review.md`); (4) ареальные данные Берёзкина — обогащение страницы Geography и `config/traditions.json` (у нас уже есть координаты традиций).

## Детали по источникам

### 1. Trilogy — ядро интеграции

Репозиторий `j-hagedorn/trilogy` (R + Java, CC-BY-SA 4.0, исходники — public domain / Ashliman's Folktexts с разрешением). В `data/` лежат:

- **`tmi.csv`** — Thompson Motif-Index. Колонки: `id` (код мотива, напр. `A1.1`), `chapter_name` (тема, напр. *Myths*), `motif_name` (название, напр. *Sun-God As Creator*), `notes` (библиография/комментарии), `level` (0–6 — глубина иерархии), `chapter_id` (буква A–Z) и `level_0…level_6` — разложенные родительские категории. То есть иерархия уже распарсена в столбцы — удобно строить дерево/префиксные запросы.
- **`atu_df.csv`** — типы сказок ATU. Колонки: `chapter`/`division`/`sub_division` (трёхуровневая рубрикация), `atu_id` (номер типа, напр. `1851`, `1855A`), `tale_name`, `litvar` (литературные варианты), `provenance` (география/традиции бытования с библиографией), `tale_type` (краткое содержание сюжета), `remarks`, `combos`.
- **`atu_seq.csv`** — **ключевая мостовая таблица** (большая, >10 МБ). Колонки: `atu_id` (джойнится с `atu_df`), `tale_variant`, `motif_order` («порядок упоминания мотива в описании типа сказки»), `motif` (**код TMI, джойнится с `tmi.csv`**). Именно она превращает тип сказки в **упорядоченную последовательность мотивов TMI** — это «нарративная ДНК» в смысле Darányi/Ofek (см. обзор).
- **`atu_combos.csv`** — пары часто комбинируемых типов: `atu_id`, `combo`.
- **`aft.csv`** — аннотированные сказки (из корпуса Д. Л. Ашлимана). Колонки: `atu_id`, `tale_title`, `provenance`, `notes`, `source`, **`text`** (полный текст сказки), `data_source`, `date_obtained`. Это размеченный текст↔тип — готовые train/eval-данные.
- **`propp.csv`** — функции Проппа.
- **`*.graphml`** — `motif_graph`, `combos_graph`, `atu_graph`: предпостроенные сети (совместимы с нашими `src/graphs/`, networkx читает GraphML напрямую).

**Цепочка связей (то, ради чего всё затевается):**

```
aft.text ──(atu_id)──▶ atu_df ──(atu_id)──▶ atu_seq ──(motif)──▶ tmi
   текст сказки          тип ATU          упоряд. мотивы        мотив TMI + иерархия + notes
```

Эта цепочка даёт сразу: (1) текст → его тип; (2) тип → каноническую последовательность мотивов; (3) мотив → место в иерархии Томпсона. Для нас это и обучающие пары, и gold-разметка для оценки кластеров.

### 2. fbkarsdorp/tmi + MOMFER

Flask-интерфейс к TMI (Apache-2.0). В `data/`: `tmi.json` (структурированный индекс), `tmi.txt`, `tmi-cleaned.txt`, `tmi-index.txt`. Формат текстового индекса — `КОД.Название` с диапазонными заголовками (`A0.-A99. Creator`) и иерархией от широких категорий к узким. Скрипты `compile_tmi.py`, `TMI_tree.py` строят дерево, `indexer.py` — Whoosh-индекс. Онлайн-аналог — **MOMFER** (`momfer.meertens.knaw.nl`, Karsdorp et al. 2015), поисковик по TMI с WordNet-обогащением (уже упомянут в `motif-induction-review.md`).

Поскольку Trilogy уже отдаёт TMI в виде разобранного CSV, fbkarsdorp полезен как: сверочный источник `notes`/полноты, источник кода для собственного поискового индекса по мотивам, и как канонический `tmi.json`, если захочется обходиться без R-выгрузки Trilogy.

### 3. База Берёзкина (mapsofmyths / areasofmyths)

«Тематическая классификация и ареальное распределение фольклорно-мифологических мотивов»: ~2 564 мотива по ~958 обществам (Азия, Африка, Америки, Европа), ≥7 456 библиографических источников — в т.ч. ~2 484 русскоязычных по Сибири, Алтаю и финно-уграм, почти отсутствующих у Томпсона; 469 источников по Африке против 58 у Томпсона. Главная единица — мотив как «эпизод или образ, простой или относительно сложный, пересказываемый минимум в двух традициях».

**Две уникальные ценности:**
- **Ареальное распределение.** Для каждого мотива — список обществ/традиций, где он зафиксирован (страницы вида `areasofmyths.com/a1.html` дают код мотива, описание, перечень традиций со ссылками на источники). Это прямой материал для географии распространения и для проверки наших кросс-культурных «affinities».
- **Соответствия с TMI/ATU.** В описаниях мотивов Берёзкина проставлены ссылки на Томпсона и другие индексы — то есть существует (частичный) cross-walk Берёзкин↔TMI↔ATU.

**Ограничения доступа.** `mapsofmyths.com/motifs` под паролем; `areasofmyths.com` — статичный фреймсет в windows-1251, без выгрузки/API; коммерческое зеркало `folkloredatabase.com` в условиях прямо **запрещает** text/data mining, скрейпинг и создание датасетов. Поэтому: **не скрейпить**. Допустимые пути — опубликованные академические выгрузки и приложения статей Берёзкина (TRAMES 2015/2018; Kunstkamera; sisu.ut.ee), готовые таблицы соответствий из них, либо прямой запрос держателям БД на исследовательский доступ. Любое использование — с атрибуцией и проверкой условий.

### 4. ATU-тезаурус (TemaTres)

`vocabularyserver.com/atu` — инсталляция **TemaTres** (open-source vocabulary server). Это значит: тезаурус выгружается в **SKOS-Core / RDF / JSON / Dublin Core**, есть постраничный доступ к каждому типу (`index.php?tema=NNN`) и связи с DBpedia (см. storynotes psychemedia). Структура — три раздела: 1–299 Animal Tales, 300–1199 Ordinary Folktales, 1200–2499 Jokes/Anecdotes/Formula Tales. Полезен как **канонический, многоязычный, версионированный словарь типов** с устойчивыми идентификаторами — в дополнение к «плоскому» `atu_df.csv` из Trilogy. Лицензия на сайте не указана — атрибутировать Uther 2004 и проверить условия перед перепубликацией.

### 5. Missouri LibGuides

`libraryguides.missouri.edu` (c.php?g=1083510 и др.) — **не конкорданс**, а кураторские списки полнотекстовых сказок, сгруппированные по номерам ATU, со ссылками на Internet Archive и краткой провенансностью. Годятся как небольшой дополнительный размеченный (ATU→текст) корпус public-domain текстов, расширяющий `aft`.

## Что конкретно извлечь

1. **Контролируемый словарь мотивов и типов** (из `tmi.csv` + ATU SKOS): ~46k мотивов TMI с иерархией A–Z и ~2 500 типов ATU. → таблица-справочник для тегирования и для UI-фильтра «по традиционному мотиву».
2. **Cross-walk таблицы:** ATU↔TMI (готова в `atu_seq.csv`), TMI↔Берёзкин и ATU↔Берёзкин (из публикаций Берёзкина), ATU↔DBpedia/Wikidata (через TemaTres-линки). → один граф соответствий между индексами.
3. **Размеченный корпус текст↔тип↔мотивы** (`aft.csv` + Missouri): обучающие/оценочные пары для детекции мотивов и классификации типов.
4. **Ареальные профили мотивов** (Берёзкин, легальным путём): мотив → множество традиций/координат. → слой для Geography и метрик близости традиций (roadmap item 4).
5. **Готовые сети** (`*.graphml` Trilogy): мотивные и комбо-графы для сравнения с нашими извлечёнными графами (`src/graphs/`).

## Как использовать в mythoscope

- **Item 1 — связать безнадзорные результаты с индексами.** Берём `aft.text`, прогоняем через текущий пайплайн (chunking → embeddings → проекции/кластеры), затем по `atu_id`→`atu_seq`→`tmi` получаем gold-набор мотивов на тех же текстах и считаем согласие кластеров с мотивами/типами (метрики из обзора: Rand Index, F1, κ). Это первый воспроизводимый бенчмарк «кластер ↔ традиционный мотив».
- **Item 2 — запрос по традиционному мотиву.** Индекс TMI/ATU (по образцу fbkarsdorp/Whoosh или нашего Chroma) рядом с семантическим поиском: пользователь выбирает мотив `A1.1` / тип ATU 300, получает (а) каноническое определение и (б) семантически близкие фрагменты нашего корпуса.
- **Fine-tune / few-shot детекции мотивов.** `aft` + `atu_seq` дают пары «текст → мотивы», воспроизводящие постановку GOLEM и Arabian Nights (см. `motif-induction-review.md`, SOTA ~0.85 F1 на fine-tuned Llama-3). Хороший задел для supervised-ветки.
- **Item 4/7 + страница Geography.** У нас уже есть `config/traditions.json` с координатами и кластеризация традиций по регионам. Ареальные профили Берёзкина (где какой мотив встречается) ложатся на эту карту напрямую и дают данные для метрик близости традиций и для визуализации распространения мотивов.
- **Графы.** GraphML Trilogy читается networkx как есть → сравнение наших извлечённых мотивных сетей (`src/graphs/`) с эталонными мотив/комбо-графами.

## Рекомендации (порядок действий)

1. **Начать с Trilogy.** Завести легковесный загрузчик (по аналогии с `src/corpus/downloader.py`): тянуть `tmi.csv`, `atu_df.csv`, `atu_seq.csv`, `atu_combos.csv`, `aft.csv` с raw GitHub, проверять контрольную сумму, хранить локально (не коммитить большие CSV — `aft`/`atu_seq` крупные; вынести в кэш / .gitignore). Атрибуция CC-BY-SA 4.0.
2. **Построить единый cross-walk** как небольшой модуль/конфиг: таблицы ATU↔TMI (из `atu_seq`), позже + Берёзкин и DBpedia. Это станет «traditional index» слоем для UI и оценки.
3. **Прототип бенчмарка (item 1)** на подмножестве `aft`: прогон через текущий пайплайн + сравнение с gold-мотивами; зафиксировать метрики.
4. **ATU из TemaTres** подключить вторым шагом через SKOS-выгрузку (стабильные ID, многоязычность, DBpedia-линки).
5. **Берёзкин — отдельной задачей и легально:** сначала извлечь ареальные таблицы и cross-ref из опубликованных приложений/статей; для полной БД — запрос на доступ. Скрейпинг `areasofmyths`/`folkloredatabase` не использовать.
6. Зафиксировать всё в этом документе и при появлении кода — в `docs/how_to.md`.

## Правовые оговорки

- **Trilogy — CC-BY-SA 4.0:** свободно использовать с атрибуцией; производные — под той же лицензией (учесть при публикации наших датасетов, roadmap «release datasets»).
- **fbkarsdorp/tmi — Apache-2.0:** пермиссивно. Сам TMI Томпсона — старый, но издания/выверки могут иметь свои условия; атрибутировать.
- **Берёзкин / folkloredatabase.com:** копирайт; data/text mining и скрейпинг **запрещены** условиями зеркала. Только опубликованные выгрузки или прямое разрешение, с атрибуцией Ю. Е. Берёзкина.
- **ATU TemaTres:** лицензия на сайте не указана; атрибуция Uther (ATU 2004), проверять условия перед перепубликацией выгрузок.
- Корпус `aft` восходит к Folktexts Д. Л. Ашлимана (public domain / с разрешением) — сохранять провенанс из колонок `source`/`data_source`.
