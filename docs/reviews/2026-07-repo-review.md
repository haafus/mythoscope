# Ревью репозитория — июль 2026

Полное ревью кодовой базы по четырём зонам (пайплайн данных, подсистема motifs,
сервер+фронтенд, тесты/инфраструктура), сведённое и отранжированное. Самые тяжёлые
находки проверены вручную по коду (отмечены ✓). Размеры для контекста: ~11.5k строк
Python в `src/`, ~4.2k строк тестов; крупнейшие модули — `app.css` (2 003),
`page-motifs.js` (1 642), `services/motifs.py` (1 587), `sources/trilogy.py` (1 224).

Сквозная тема: **код аккуратный и хорошо документированный, но ничего не
энфорсится** — CI отсутствует полностью, и почти все баги ниже из категории
«тихо, без ошибки».

## 2. Багфиксы (по убыванию тяжести; у каждого — сценарий отказа)

### P0 — потеря данных / сломанная установка

**B1 ✓ `mytho clean --apply` удаляет эмбеддинги деактивированных моделей.**
`pipeline_inspect.embeddings_orphan_collections` (`:130-139`) строит `known_keys`
из `list_embedding_aliases()`, которая читает **только** секцию
`embedding.models` (`model_registry.py:54-55`) — тогда как `model_name_for_key`
(`:62-68`) явно считает `inactive` известными. Сценарий: перенёс модель в
`inactive` → `mytho clean --apply` → её Chroma-коллекция молча уничтожена.
Фикс: учитывать обе секции при вычислении орфанов.

**B2 ✓ Установленный wheel сломан: `fetch_cache` нет в `py-modules`.**
`pyproject.toml:76-79` перечисляет top-level модули, но не `fetch_cache`, который
импортируют `corpus/builder.py:9` и `motifs/sources/fetch.py:9`. `pip install` +
запуск corpus/motifs → `ModuleNotFoundError`. Тесты не ловят (гоняются из
исходников с `src` в `sys.path`).

**B3. Смена вёрстки источника молча затирает хорошие данные пустыми.**
Парсеры при изменении HTML деградируют в `[]` (`berezkin.py:380-390` и др.),
а `build_motifs` логирует count и **перезаписывает** рабочий
`outputs/motifs/*.json` пустым результатом (`build_motifs.py:71-74`); сломанный
парс даже не перефетчится без `--force`. Та же族 проблема: новая незакрытая
кавычка в TMI CSV тихо съедает тысячи строк (`trilogy.py:33-36` чинит только один
известный случай). Фикс: sanity-floor на счётчики («berezkin > N, tmi > N, иначе
abort»).

**B4. `corpus.json` пишется неатомарно и только в самом конце.**
`builder.py:227-228`: Ctrl+C на большом прогоне → все скачанные `.txt` становятся
неучтёнными орфанами (метаданные не сохранились), а падение во время самой записи
корёжит `corpus.json` (нет temp+rename). Фикс: `save_json` + периодический флаш.

### P1 — видимое неверное поведение

**B5 ✓ Висячие Berezkin→ATU ссылки (асимметрия с TMI-стороной).**
`crosswalk.py:190-204` сохраняет каждый `_resolve_atu(ref)` безусловно, тогда как
Berezkin→TMI фильтрует `if r in tmi_ids` (`:216`); `_resolve_atu` фолбэчит в
`ref.rstrip("*")` для неизвестных. Плюс `_BARE_ATU_RE` (`berezkin.py:42`)
перематчивает токены вроде `1920s` → «тип 1920S» проходит shape-фильтр. Итог:
мёртвые ссылки на несуществующие типы на страницах Берёзкина. Фикс: зеркальный
`if r in atu_ids` + ужесточить regex.

**B6. Гонки async-навигации в SPA (нет request-id guard).**
`openMotif`/`loadList`/`browseRoot`/`renderOverview` (`page-motifs.js:466-501` и
др.) безусловно пишут `innerHTML` после `await`. Клик A → быстро B: медленный
ответ A приходит последним и затирает деталь B, при этом `selectedId`/URL — B.
На embeddings-странице guard уже есть (`page-embeddings.js:311-324`) — перенести
паттерн. Родственные: таймер поиска не чистится при уходе со страницы
(`:267-271` — через 250 мс `syncUrl` перепишет адресную строку **чужой**
страницы на `#/motifs?q=…`); утечка Cytoscape-инстансов при быстрой смене книг
(`page-graphs.js:94-126`); та же гонка в corpus-ридере (`page-corpus.py:97-114`).

**B7. Серверный кеш не инвалидируется до конца жизни процесса.**
`motifs/store.py:70-87`: `clear_cache()` никто не зовёт, файлы не отслеживаются.
Пересобрал `mytho motifs` при работающем сервере → сервер бесконечно отдаёт
старые данные без единого сигнала. Фикс: mtime-инвалидация или admin-reload.

**B8. `mytho status` всегда показывает projections 5/6 (жёлтым).**
`pipeline_inspect.py:188` включает `summaries_umap` в знаменатель, но артефакт
пишется только с opt-in `--summaries`, который `build` не передаёт. Нормальный
успешный прогон никогда не «зелёный».

**B9. Лимит `rpd` парсится, логируется и — не работает.**
`rate_limiter.py:79-87`: дневного bucket'а нет, только RPM/TPM. Пользователь,
поставивший `"rpd": 10000`, защиты не получает — узнает от 429-стены провайдера.

**B10. Кеш семантических эмбеддингов валидируется только длиной.**
`semantic_parallels.py:88-104`: правка определения при неизменном числе мотивов →
молча переиспользуются старые вектора, параллели неверные. Фикс: content-hash
входных текстов.

**B11. Недетерминизм от прогона к прогону.**
`parallels.py:187-200`: порядок `triangles` зависит от hash-seed (итерация по
set-пересечению, tie-break только по score) — churn в `parallels.json`.
`corpus/utils.py:93-103`: цвета традиций — несидированный `random` — меняются
при каждой пересборке. Фикс: стабильные вторичные ключи сортировки / seed по
имени традиции. Подробный разбор всей системы цветов (бэк + фронт, места
хранения и дубли) — в [`color-system-review.md`](archive/color-system-review.md).

### P2 — латентные риски и гигиена

**B12. XSS-стоки, безопасные «только пока».** `introHtml` инжектит
`intro.blurb`/`citation` как есть (`page-motifs.js:1035,1038`), attestation-ветки
инжектят `e.cite`, `d.summary_html` доверяется серверному эскейпу — всё живо лишь
потому, что данные сегодня — серверные константы или пре-эскейплены. Экранировать
на стоке; ввести tagged-template-хелпер (см. R1). Плюс расхождение контрактов:
сервер эскейпит `quote=False`, клиент — с кавычками.

**B13. Дрифт документации и конфигов.** Четыре разных числа TMI-мотивов в доках
(46 230 / 46 238 / 46 248 / 46 215); `mockups/README.md` описывает «три
прототипа» при девяти существующих; `.env.example:26` рекламирует несуществующий
`MYTHO_EMBEDDING__DEFAULT_CHUNKING` (pydantic молча игнорирует). Системный фикс —
манифест счётчиков (см. F8).

**B14. Разное по мелочи.** Расхождение экстракции имени сущности между дедупером
(`extraction.py:54`, три варианта регистра) и индексером графа
(`graph_generator.py:19-29`, любые варианты) — тихая потеря атрибутов;
`_concept_erasure` печатает прогресс `print(..., end="\r")` мимо логгера
(`visualization.py:75-88`); `services/corpus.py:18` — `json.load` без
try/except (битый `corpus.json` кладёт три эндпоинта разом); фиксированный ключ
кеша Wikidata не кодирует SPARQL-запрос (`atu_wikidata.py:33`) — правка `_QUERY`
молча переиспользует старый ответ; участники `reasoned_parallels.GROUPS` не
валидируются при сборке — опечатка в id = молча отсутствующая ссылка.

## 3. Следующие сильные фичи (по убыванию отдачи)

**F1. CI — самый дешёвый и самый высокий рычаг.** `.github/` не существует, при
том что ruff/mypy/pytest/`node --test` уже настроены. Один workflow: lint →
typecheck → тесты → JS-тесты; отдельной джобой — packaging-smoke (`pip install`
wheel в чистый venv + `mytho status` — поймал бы B2) и golden-тесты stats-билдеров
(снапшот `stats()` трёх индексов на `tiny_db`-фикстуре — закрывает ~1 000
непокрытых строк, питающих live-роут). Зарегистрировать маркеры
`slow`/`integration` и выключить по умолчанию тест, качающий гигабайты весов.

**F2. Детекция мотивов в корпусе (соединить две половины проекта).** Сейчас
корпус текстов и каталоги мотивов живут параллельно. Рецепт уже доказан
экспериментом `mockups/10-motif-text-embedding-eval`: эмбеддинги `name+summary` ×
чанки текста дают recall, LLM-верификация кандидатов — precision. Продуктовая
форма: страница текста показывает найденные мотивы с привязкой к месту, страница
мотива — тексты корпуса, где он встречается. Это флагманская фича, к которой
проект структурно готов.

**F3. Очередь ревью кросс-волка из `triangles`.** Трёхсторонние треугольники уже
вычисляются с полем `missing` — какое из трёх рёбер (BZ-TMI / BZ-ATU / ATU-TMI)
отсутствует в подтверждённом кросс-волке (`parallels.py:186-200`), — но не имеют
ни одного потребителя. Это готовая витрина «предложить недостающую связь»:
списком с сортировкой по score, кнопкой «принять в crosswalk».

**F4. Поверхность для библиографии Берёзкина.** `berezkin_bibliography.json`
уже строит per-motif дерево регион→цитаты, карту работ→макро-ареалы и
`area_index` (`berezkin_bibliography.py:337-349`) — на странице мотива и в
overview можно показывать «какие работы документируют какие регионы».

**F5. Поиск по старым номерам + провенанс изданий.** Alias-карты (AaTh→ATU,
TMI 1-е изд.→ревизия) полны и уже резолвят прямую навигацию; осталось подключить
их к поиску («ввёл AaTh 425A — нашёл ATU 425A») и показать «ранее известен как»
как полноценный блок.

**F6. Дожать уже отдаваемые, но неиспользуемые данные.**
- Клик из результатов поиска в ридер/источник: `SearchResult.url` отдаётся, но не
  рендерится (`search-utils.js:74-86`), а deep-link-плюмбинг ридера уже есть.
- `/api/motifs/{index}/cultures` реализован и не используется — готовое семя для
  фильтра по культурам.
- Wikisource-линки (полные тексты сказок) и concordances (KHM/Perry/Child)
  собраны, но едва видны в UI.
- `semantic_parallels` «novel_only» (~21k совпадений по смыслу без лексики) —
  только счётчик; это отдельная discovery-витрина.
- Легенда рёбер + поиск узла в графах (`page-graphs.js`), подсказка о горячих
  клавишах на motifs-странице.

**F7. Языковой/ареальный фасет из традиций.** У традиций mapsofmyths есть
4-уровневый `areal_path` и языковая семья (`mapsofmyths.py:92-114`) — это
drill-down ареального распределения и фасет по языковым семьям, которых нет в UI.

**F8. Манифест данных + шаг валидации в `mytho build`.** Проверять счётчики
собранной БД против закоммиченного манифеста: ловит и регрессии пайплайна
(B3), и дрифт доков (B13) — манифест становится единственным источником истины,
на который ссылаются доки.

**F9. Довести полуготовые возможности пайплайна.** Enforcement `rpd` (плюмбинг
на 90% готов, см. B9); OCR-fallback для сканированных PDF (ветка «нет текста» уже
детектится, `extraction.py:114-119`); мульти-модельная сборка эмбеддингов из CLI
(внутренний цикл уже есть); флаг `--include-inactive`/команды enable-disable для
локальных моделей (сейчас clean с ними воюет — B1).

## Приложение: карта покрытия тестами

Хорошо покрыто: парсеры motifs-источников (137 тестов), chroma/chunking/
model_manager, схемы сервера. **Не покрыто вовсе**: stats-слой
(`services/motifs.py:529-983`, живой роут), весь `projections/` кроме utils
(включая численную математику `_concept_erasure`), `build_embeddings.py`
(путь corpus→Chroma), большинство JS (2 файла из ~15). `tests/test_motifs.py`
(1 598 строк, 17 классов) стоит разбить по модулям-источникам; общую
`tiny_db`-фикстуру — поднять в `conftest.py` (сейчас продублирована трижды).
