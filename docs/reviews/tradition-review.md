# Разбор поля `tradition` (бэк + config + фронт)

Аудит того, где `tradition` задаётся, хранится, передаётся и используется, со
всеми местами хранения, дублями и нелогичностями. Состояние на коммит `13039cc`.
Это аналитический документ — код по нему ещё не менялся.

В отличие от двух соседних обзоров, `tradition` — **не производное** (как
`major_tradition`, см. `major-tradition-review.md`) и **не сгенерированное** (как
цвет, см. `color-system-review.md`) поле, а **исходное, авторское**: оно прямо
прописано в `config/corpus.json` на каждой книге, и именно вокруг него крутятся оба
других. Поэтому и картина, и выводы смещаются: претензии про денормализацию,
асимметрию served-стора и недетерминизм здесь **снимаются**, а на первый план
выходит другое — **`tradition` это ненормализованный свободный строковый
join-ключ, связывающий два конфиг-файла нестрогим равенством строк, без всякой
валидации.**

## 1. Где задаётся (source, не build-time)

`tradition` — вход, а не результат. Он написан руками в `config/corpus.json`, по
одному на книгу (28 записей), рядом с `title`/`url`/`description`:

```json
{ "title": "The Poetic Edda", "tradition": "Norse", "url": "...", "description": "..." }
```

Никакого шага резолюции/генерации нет. На сборке (`corpus/builder.py`) значение
просто протаскивается в метаданные (`_build_metadata`) и в путь на диске
(`builder.py:91`, `text_path` → `corpus_dir/<major>/<tradition>/<title>.txt`).

**Именно `tradition` — вход для обоих соседних полей:**
- цвет: `get_tradition_color(trad)` (`builder.py:154`, `utils.py:93`) ключуется по строке традиции;
- major: `_tradition_major_map(...).get(tradition, "")` (`builder.py:187`) резолвится из неё.

## 2. Где config определяет традиции — в двух местах

1. **`config/corpus.json`** — какая традиция у каждой книги (авторское поле).
2. **`config/traditions.json`** — дерево `major → {traditions: {<tradition>: {description, coordinates}}}`, где имена традиций суть **ключи** словаря `traditions`.

Связь между ними — **только совпадение строки**: традиция книги из (1) должна
буквально равняться ключу в (2). Никакого общего справочника/enum/id, гарантирующего
это, нет (грепом `canonical/enum/valid_tradition` по `corpus/`+`server/` — пусто).

## 3. Где хранятся (все места)

| Место | Что | Жизнь |
|---|---|---|
| `config/corpus.json` → `tradition` | **источник правды: у какой книги какая традиция** | в репозитории |
| `config/traditions.json` → **ключи** `traditions.*` | источник правды: метаданные традиции (desc/coords) | в репозитории |
| `outputs/corpus/corpus.json` → `rows[i].tradition` | копия на строку (корректная гранулярность — поле книжного уровня) | на диске, пересборка |
| `outputs/corpus/traditions.json` → **ключи** | served-метаданные традиции (+ `color`, `books`) | на диске, пересборка |
| Структура каталогов на диске | `tradition` = второй сегмент пути | на диске |
| Метаданные чанков ChromaDB | `tradition` в каждом чанке (`build_embeddings.py`, из `CorpusFileInfo`) | `outputs/embeddings/` |
| `state.corpusDocuments` / `state.traditionInfo` (фронт) | строки каталога / карта традиций | на сессию |
| `state.corpusOpenTraditions` | составные ключи `major|tradition` | на сессию |

Ключевое отличие от major: **served `traditions.json` традицию НЕ выбрасывает — она
там ключ.** То есть `tradition` — это **join-ключ**, по которому документ сшивается
с метаданными традиции.

## 4. Как передаётся на фронт

- **`/api/corpus/catalog`** (`services/corpus.py:10-36`) — `tradition` на каждом
  документе (спред строки), плюс здесь же join: `traditions_info.get(row["tradition"],
  {})` (`corpus.py:25`) добавляет `color`. Схема `CorpusDocument.tradition: str = ""`
  (`schemas.py:41`).
- **`/api/corpus/traditions`** (`traditions_with_books`) — традиция как **ключ** ответа
  (`TraditionsResponse.traditions: dict`). Единственный источник метаданных традиции
  (color/coordinates/books) на фронте.
- **`/api/corpus/documents`** — `tradition` как query-параметр для сборки пути к файлу.
- **`/api/similarity/search` и `/points/...`** — `SearchResult.tradition: str = "Unknown"`
  (`schemas.py:29`), заполняется из Chroma-метаданных. **И, в отличие от major, реально
  используется фронтом** (см. ниже).

## 5. Где используются (фронт) — существенно шире, чем major

- **`core.js:178-192` `groupDocuments`** — второй уровень группировки:
  `const tradition = doc.tradition || "Unknown";` → `Map<major, Map<tradition, docs[]>>`.
- **`core.js:174-176` `corpusTraditionKey`** — `` `${major||"Other"}|${tradition||"Unknown"}` `` (ключ open/collapse).
- **`tree-sources.js` / `tree-traditions.js`** — традиция это **лист** дерева: имя,
  цветная точка (`docs[0].color`, keyed by tradition), клик = выбор традиции.
- **`page-corpus.js:67`** — метка info-панели `… / ${doc.tradition || "Unknown"}`.
- **`page-geography.js`** — маркеры строятся **по традиции** (`buildCoordinateGroups`,
  координаты из `traditionInfo`, цвет `info.color` иначе `#334155`); deep-link
  `#/corpus?...&tradition=<name>` (`:97`) снова завязан на строку имени.
- **`page-embeddings.js` / `search-utils.js`** — раскраска scatter по традиции
  (`page-embeddings.js:32`), результаты поиска печатают `result.tradition`
  (`search-utils.js:45,79`), `tradition-select`/`highlightTradition` (`:300`).

То есть `tradition` — **сквозной идентификатор сущности** через все разделы, тогда
как major жил только в двух деревьях + метке.

## 6. Сортировка / порядок

Серверная сортировка каталога `(major_tradition, tradition, title)`
(`services/corpus.py:28-34`) упорядочивает и по традиции (внутри major, алфавитно).
Плюс `traditions_with_books` сортирует книги внутри традиции
(`corpus.py:48`, `sorted(...)`). Отдельной фронтовой сортировки по традиции нет
(деревья идут в порядке уже отсортированного массива).

## 7. Дубли, избыточность, нелогичности

1. **Нет канонической идентичности традиции.** Ни списка, ни enum, ни id — только
   свободная строка, живущая в двух конфиг-файлах.
2. **Хрупкий строковый join (главный риск).** Сшивка `corpus.json.tradition` ↔ ключи
   `traditions.json` идёт по **точному равенству строки**. Любой рассинхрон (опечатка,
   регистр, «Norse» vs «Norse mythology») **молча ломает всё производное**:
   `traditions_info.get(...)` → `{}` → цвет и координаты уходят в дефолт;
   `_tradition_major_map.get(...)` → `""` → книга падает в секцию `Other`; на гео-карте
   традиция без координат просто исчезает. Ни ошибки, ни варнинга на сервинге — тихая
   деградация. (Билдер логирует WARNING только про пустой major, `builder.py:188`.)
3. **Разъехавшиеся дефолты «нет традиции»** — как и у соседей, но здесь их видно даже
   внутри одного файла схем:
   - `SearchResult.tradition = "Unknown"` (`schemas.py:29`),
   - `CorpusDocument.tradition = ""` (`schemas.py:41`),
   - итератор эмбеддингов → `"unknown"` (`iterator.py:58`),
   - фронт (группировка/ключ/метки) → `"Unknown"` (`core.js`, `search-utils.js`, `page-corpus.js`).
   Одна ситуация — три написания (`""`, `"unknown"`, `"Unknown"`).
4. **Денормализация — НЕ дефект (в отличие от major/цвета).** `tradition` на каждой
   строке — это корректная гранулярность: традиция действительно атрибут книги.
5. **Асимметрии served-стора нет** — традиция сохраняется как ключ `traditions.json`
   (в отличие от выброшенного major).

## 8. Чем этот разбор отличается от обзоров цвета и major

| | цвет | major_tradition | **tradition** |
|---|---|---|---|
| Природа поля | сгенерировано (рандом) на сборке | выведено из дерева на сборке | **авторский вход** |
| Источник правды | `traditions.json` (после генерации) | ключ дерева `config` | **`config/corpus.json` + ключи `traditions.json`** |
| Денормализация на книгу | дефект (атрибут традиции) | дефект (атрибут традиции) | **корректно (атрибут книги)** |
| В served `traditions.json` | есть (`color`) | **выброшен** | **есть (это ключ)** |
| Роль | оформление | группировка/секции | **сквозной join-ключ сущности** |
| Главная болячка | недетерминизм + контраст | 3 дефолта + асимметрия | **нет канонической идентичности; хрупкий строковый join** |
| Общее со всеми | — | разные дефолты «нет значения» | разные дефолты «нет значения» |

## Что напрашивается (на будущее, не реализовано)

- **Каноническая идентичность традиции** — единый справочник (или стабильный `id`/slug
  вместо имени-строки как ключа), общий для `corpus.json` и `traditions.json`; join по
  id, а имя — только для показа.
- **Валидация на сборке** — падать/громко варнить, если `tradition` книги нет среди
  ключей `traditions.json` (сейчас молчит, деградирует тихо).
- **Единый дефолт** «нет традиции» вместо `""` / `"unknown"` / `"Unknown"`.
